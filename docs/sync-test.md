# M0 — 운동 기록 갱신 주기 검증 가이드

코딩 전에 확인할 것: **Apple Watch로 운동을 끝냈을 때 아이폰 단축어가 언제 실행되는지, 그 시점에 운동·심박·칼로리 데이터가 이미 아이폰에 들어와 있는지.**
서버 없이 아이폰 **메모** 앱에 기록을 남겨 측정한다. 10분이면 설정할 수 있다.

---

## 1. 테스트 단축어 만들기: `WB 동기화 테스트`

단축어 앱 → `+` → 아래 동작을 순서대로 추가한다.
동작 이름은 iOS 버전에 따라 조금 다를 수 있다. 변수를 탭하면 나오는 속성 목록에서 고르면 된다.

1. **건강 샘플 찾기**
   - 유형: `운동` · 정렬 기준: `시작 날짜`, `최신순` · 제한: `1`
   - 결과 변수 이름 → `최근운동`
2. **건강 샘플 찾기**
   - 유형: `심박수`
   - 필터: `시작 날짜`가 `최근운동.시작 날짜` **이후**이고, `종료 날짜`가 `최근운동.종료 날짜` **이전**
   - 결과 변수 이름 → `심박`
3. **개수 세기**: `심박` → 변수 `심박개수`
4. **통계 계산**: `평균`, 입력 `심박` → 변수 `심박평균`
5. **통계 계산**: `최대`, 입력 `심박` → 변수 `심박최대`
6. **건강 샘플 찾기**
   - 유형: `활동 에너지` · 필터는 2번과 같은 구간
   - 결과 → **통계 계산** `합계` → 변수 `칼로리`
7. **텍스트**: 아래 한 줄 (꺾쇠 부분은 변수를 넣는다)
   ```
   [<현재 날짜 HH:mm:ss>] <단축어 입력 또는 "수동"> | 운동=<최근운동.종류> 종료=<최근운동.종료 날짜 HH:mm:ss> 시간=<최근운동.지속 시간> | HR n=<심박개수> avg=<심박평균> max=<심박최대> | kcal=<칼로리>
   ```
8. **메모에 추가**: 메모 `WB 동기화 로그` (먼저 빈 메모를 만들어 둔다)

## 2. 자동화 연결

단축어 앱 → **자동화** 탭 → `+` → **Apple Watch 운동**
- `종료 시` 선택 · 운동 종류는 `모든 운동`
- **즉시 실행** 선택 (`실행 시 알림`은 끈다)
- 실행할 단축어: `WB 동기화 테스트`

## 3. 측정 시나리오

시나리오마다 운동을 짧게(5~10분이면 충분) 하고, 끝난 뒤 **10분 뒤**와 **1시간 뒤**에 단축어를 **수동으로 한 번 더 실행**한다. 그러면 메모에 같은 운동 줄이 3개 생기고, 값이 늘어났는지 비교할 수 있다.

| # | 상황 | 확인 포인트 |
|---|---|---|
| S1 | 아이폰 **잠금 해제**, 워치 옆에 있음 | 기준값 |
| S2 | 아이폰 **잠김**(주머니 속), 워치 옆에 있음 | 잠금 상태에서 건강 데이터를 읽을 수 있는지, 실패 알림이 뜨는지 |
| S3 | **워치만 차고** 운동(아이폰은 집에 둠) → 귀가 | 자동화가 귀가 후에 실행되는지, 아예 실행되지 않는지 |
| S4 | 아내 폰에서 S1 또는 S2 1회 | 기기와 iOS 버전 차이 |

> 실행 중 오류 알림("건강 데이터에 접근할 수 없음" 등)이 뜨면 화면을 캡처하거나 시각을 적어 둔다. 메모에 줄이 생기지 않는 것도 중요한 결과다.

## 5. 결과에 따라 정할 것

| 관찰 | 결정 |
|---|---|
| 자동 실행 때 HR/kcal이 +10분 값보다 적다 | 실시간 단축어 앞에 `대기 N초`를 넣거나, 실시간 전송은 "운동 종류·시간"만 믿고 값은 재동기화로 덮어쓴다 (upsert라 가능) |
| S2에서 실패한다 | 일일 재동기화를 여러 번(예: 12·18·22시) 돌린다 |
| S3에서 자동화가 실행되지 않는다 | 재동기화가 유일한 안전망이므로 최근 7일 범위를 유지한다 |
| 모든 시나리오가 정상이다 | 하루 1회(22시) 재동기화로 충분하다. 성공 기준을 "5분 이내"로 확정한다 |

결과표를 채워서 알려 주면 PRD의 C1/C2와 9장 성공 기준에 반영한다.
