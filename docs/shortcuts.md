# iOS 단축어 만들기 (M2 — 데이터 수집)

아이폰 **단축어** 앱으로 Apple 건강의 운동 기록을 운동보드 서버(Apps Script)에 보내는 방법이다. 코딩 지식은 필요 없고 동작(액션)을 순서대로 쌓으면 된다.

> **먼저 알아둘 점**: 단축어 동작·속성의 한글 이름은 iOS 버전과 언어 설정에 따라 조금씩 다르다. 이 문서의 이름은 흔한 표기이며, 비슷한 것을 고르면 된다. 처음 만들 때는 아래 **"중간 확인"** 에서 결과를 눈으로 확인한다. 이 문서는 실제 기기에서 검증하기 전의 초안이며, 확인할 항목은 [10장](#10-기기에서-직접-확인해야-하는-것)에 모았다.

| 단축어/자동화 | 역할 |
|---|---|
| `WB 동기화` (핵심) | 입력받은 **일수** 안에 시작한 운동을 전부 서버로 보내고, 결과 JSON 텍스트를 출력한다. 입력이 없거나 양의 정수가 아니면 7일 |
| `WB 과거 업로드` | 일수를 물어본 뒤(기본 365) `WB 동기화`를 실행하고 결과를 보여 준다 |
| 자동화 1: Apple Watch 운동 종료 | 60초 기다린 뒤 `WB 동기화`(1일) |
| 자동화 2~4: 12:00, 18:00, 22:00 | `WB 동기화`(7일) |

서버는 같은 운동이 다시 오면 **덮어쓰기**(upsert)한다. 몇 번을 보내도 중복되지 않고, 이번에 빈 값으로 보내도 기존 심박/칼로리는 지워지지 않는다.

## 1. 준비물

1. **웹앱 URL**(배포된 `/exec` 주소, 비밀 아님):
   ```
   https://script.google.com/macros/s/AKfycbxLF6uVdEdSz-nT_7QrqJ-MdqzteO7PkeUzMmHyPO_SQoabq3MkDxdqr-erXvkJw3Zb/exec
   ```
2. **내 쓰기 토큰**(`WRITE_TOKEN_ME`): Apps Script 편집기 → **프로젝트 설정**(톱니) → **스크립트 속성**에서 복사. 아내 것은 `WRITE_TOKEN_WIFE`.
   - 토큰은 비밀번호다. URL, 스크린샷, 메신저 본문에 넣지 않는다. 아이폰으로는 유니버설 클립보드나 AirDrop으로 옮긴다.
3. 건강 앱에 운동 기록이 있어야 한다(Apple Watch로 운동하면 자동으로 쌓임).
4. 백엔드가 최신 버전으로 재배포되어 있어야 한다(`backend/README.md`의 "변경 이력" 참고).

> 자동화는 단축어 앱의 **개인용 자동화**로 만든다. 별도의 전역 허용 스위치는 필요 없고, 각 자동화마다 **즉시 실행**과 **실행 시 알림 끄기**를 설정한다([4장](#4-자동화-만들기)).

## 2. `WB 동기화` 만들기

단축어 앱 → `+` → 이름 `WB 동기화`. 동작 검색창에 이름을 입력해 추가한다. "**변수 설정 `X`**"는 바로 앞 동작의 결과를 이름 `X`로 저장한다는 뜻이다.

### 2-A. 설정 (맨 위 3개)

1. **텍스트** `me`(아내는 `wife`) → **변수 설정** `USER`
2. **텍스트** 내 쓰기 토큰 → **변수 설정** `TOKEN`
3. **텍스트** 위 웹앱 URL → **변수 설정** `URL`

> `USER`와 `TOKEN`의 텍스트 동작은 [8장](#8-아내에게-공유하기)에서 가져오기 질문과 연결한다.

### 2-B. 며칠치를 볼지 정하기 (기본 7)

4. **숫자** `7` → **변수 설정** `일수`  (기본값을 먼저 정해 둔다)
5. **만약** `단축어 입력`이 `숫자`이고 `0`보다 **크면**(양의 정수)
   - **숫자 가져오기**(`단축어 입력`에서) → **변수 설정** `일수`
   - **End If**
   - 입력이 없거나 글자, 0, 음수면 5가 건너뛰어져 `일수`는 7로 남는다.
6. **현재 날짜** → **날짜 조정**: `일수`일 **빼기** → **변수 설정** `시작기준`
   - 즉 창은 "지금 − N×24시간 ~ 지금"이고, 운동의 **시작 날짜**가 그 안이면 대상이다. (`날짜 조정`이 `날짜 계산`으로 보일 수 있음)

### 2-C. 운동 찾기

7. **건강 샘플 찾기**: 유형 `운동` · 필터 `시작 날짜`가 `시작기준` **이후** · 정렬 `시작 날짜`, 오래된 순 · 제한 끔 → **변수 설정** `운동목록`
8. **개수 세기**: `운동목록` → **변수 설정** `운동수`
9. **만약** `운동수`가 `0`이면
   - **텍스트** `{"ok":true,"inserted":0,"updated":0,"rejected":[]}`
   - **중단 및 출력**(Stop and Output): 위 텍스트
   - **End If**
   - 운동이 0건이면 서버로 요청을 보내지 않고, 정상 응답과 같은 모양의 텍스트를 돌려주며 끝난다.

### 2-D. 운동마다 JSON 한 줄 만들기

10. **각 항목 반복**: 입력 `운동목록`. **반복 안쪽**에 아래 D-1 ~ D-13을 넣는다. 현재 항목은 `반복 항목`.

    **D-1. 변수 초기화(매 반복의 맨 처음)**: 이전 운동의 값이 남지 않게 한다.
    - **텍스트**(내용 비움) → **변수 설정** `평균심박`
    - **텍스트**(내용 비움) → **변수 설정** `최고심박`
    - **텍스트**(내용 비움) → **변수 설정** `칼로리`

    **D-2. 시작/종료**
    - `반복 항목`의 `시작 날짜` → **변수 설정** `시작`
    - `반복 항목`의 `종료 날짜` → **변수 설정** `종료`
    - (이 두 날짜 변수는 아래 D-5, D-9의 샘플 조회에서 **원본 날짜 그대로** 쓴다. ISO 텍스트가 아니다.)

    **D-3. ISO 텍스트**
    - **날짜 형식 지정**: 날짜 `시작` · 형식 `ISO 8601` · **시간 포함** 켬 → **변수 설정** `시작ISO`
    - **날짜 형식 지정**: 날짜 `종료` · 같은 설정 → **변수 설정** `종료ISO`
    - 결과가 `2026-11-22T07:05:00+09:00`처럼 **끝에 `+09:00`** 이 있어야 한다. 서버는 오프셋(또는 `Z`)이 없으면 거부한다.

    **D-4. 운동 종류 정리**
    - `반복 항목`의 **종류 속성**(아래 "종류 속성 확인" 참고) → **텍스트 대치**: `"`를 빈 텍스트로 → **텍스트 대치**: `\`를 빈 텍스트로 → **텍스트 대치**: 줄바꿈(`⏎`)을 빈 텍스트로 → **변수 설정** `종류`
    - JSON을 깨뜨릴 수 있는 문자(큰따옴표, 역슬래시, 줄바꿈)를 미리 제거한다. 줄바꿈은 입력창에서 줄바꿈 키로 넣는다.

    **D-5. 심박 샘플 조회**
    - **건강 샘플 찾기**: 유형 `심박수` · 필터
      - `시작 날짜`가 `시작`과 **같거나 이후**(이후만 보이면 그대로 `이후`)
      - `시작 날짜`가 `종료` **이전**
      - `출처`가 **내 Apple Watch** (아래 "출처 고르기" 참고)
    - → **변수 설정** `심박샘플`
    - **개수 세기**: `심박샘플` → **변수 설정** `심박수`

    **D-6. 심박 통계 (샘플이 있을 때만)**
    - **만약** `심박수`가 `0`보다 **크면**
      - **건강 샘플의 세부사항 가져오기**: 입력 `심박샘플` · 세부사항 `값` → **변수 설정** `심박값`
      - **통계 계산**: `평균`, 입력 `심박값` → **숫자 반올림**(소수점 `0`자리) → **변수 설정** `평균심박`
      - **통계 계산**: `최대`, 입력 `심박값` → **숫자 반올림**(소수점 `0`자리) → **변수 설정** `최고심박`
    - **End If**
    - 샘플이 없으면 D-1에서 비워 둔 상태(빈 텍스트)로 남고, 서버는 빈칸으로 저장한다(이미 저장된 값이 있으면 유지).

    **D-7. 칼로리 샘플 조회**
    - **건강 샘플 찾기**: 유형 `활동 에너지` · D-5와 **같은 세 필터**(시작 이후, 종료 이전, 출처) → **변수 설정** `에너지샘플`
    - **개수 세기**: `에너지샘플` → **변수 설정** `에너지수`

    **D-8. 칼로리 합계 (샘플이 있을 때만)**
    - **만약** `에너지수`가 `0`보다 **크면**
      - **건강 샘플의 세부사항 가져오기**: 입력 `에너지샘플` · 세부사항 `값` → **변수 설정** `에너지값`
      - **통계 계산**: `합계`, 입력 `에너지값` → **숫자 반올림**(소수점 `0`자리) → **변수 설정** `칼로리`
    - **End If**

    **D-9. 한 줄 JSON** — **텍스트** (큰따옴표와 쉼표까지 그대로, `⟦ ⟧` 자리에 해당 변수를 삽입):
    ```
    {"type":"⟦종류⟧","start":"⟦시작ISO⟧","end":"⟦종료ISO⟧","active_kcal":"⟦칼로리⟧","avg_hr":"⟦평균심박⟧","max_hr":"⟦최고심박⟧"}
    ```
    - 모든 값은 큰따옴표 안의 문자열이다. 값이 빈 텍스트면 `""`가 되어 JSON이 깨지지 않는다.
    - 이 텍스트가 반복의 결과(`반복 결과`)로 쌓인다. 따로 변수 설정하지 않는다.

11. **End Repeat** 뒤에: **변수 설정** `줄목록`을 `반복 결과`로.

> **소수점 표기**: 아이폰 지역이 **대한민국**(소수점 `.`)이어야 한다. 소수점이 `,`인 지역이면 `310,4`처럼 만들어져 서버가 모호한 값으로 보고 **거부(빈칸 처리)** 한다. 위에서 소수점 0자리로 반올림하므로 보통 정수가 나오지만, 지역 설정은 확인해 둔다.

#### 종류 속성 확인 (기기에서 꼭 확인)

운동 샘플에서 운동 이름(예: 달리기)이 나오는 속성이 무엇인지는 iOS 버전마다 다르다(`종류`/`유형`/`이름`/`운동 유형` 중 하나).

1. 서로 다른 운동 두 개(예: **달리기**와 **근력 운동**)를 최근에 해 둔다.
2. D-4 자리에 임시로 **빠른 보기**를 넣고, `반복 항목`의 각 속성을 하나씩 바꿔 가며 실행해 두 운동의 이름이 **서로 다르게** 나오는 속성을 찾는다.
3. 그 속성을 D-4에서 쓴다.
4. 만약 모든 속성이 `운동`(또는 같은 값)만 보인다면 그대로 `운동`으로 보낸다(대시보드는 알 수 없는 종류를 🏅로 표시한다). 이 경우 결과를 알려 달라.

#### 출처 고르기

`건강 샘플 찾기`의 필터 추가 → **출처** → 목록에서 **내 Apple Watch**(예: `○○의 Apple Watch`)를 선택한다. 아이폰 걸음 수 같은 다른 출처가 섞이는 것을 막고, 워치가 두 개거나 서드파티 앱이 같은 시간대 샘플을 쓰는 중복을 피한다. 목록에 워치가 안 보이면 해당 종류의 샘플이 아직 없는 것이다(운동을 한 번 하고 다시 선택).

### 2-E. JSON 본문 만들기

12. **텍스트 결합**: 입력 `줄목록` · 구분 기호 **사용자 지정** `,`(쉼표 하나) → **변수 설정** `운동배열`
13. **텍스트**:
    ```
    {"token":"⟦TOKEN⟧","user":"⟦USER⟧","workouts":[⟦운동배열⟧]}
    ```
    `[`와 `]`는 직접 입력하고 그 사이에 `운동배열`을 삽입한다 → **변수 설정** `본문`

### 중간 확인 (꼭 하기)

`본문` 다음에 임시로 **빠른 보기**를 넣고 `본문`을 입력으로 준 뒤 단축어를 **수동 실행**한다. 이렇게 보여야 한다.

```
{"token":"xxxxxxxx…","user":"me","workouts":[{"type":"실외 달리기","start":"2026-11-22T07:05:00+09:00","end":"2026-11-22T07:37:30+09:00","active_kcal":"310","avg_hr":"142","max_hr":"171"},{"type":"요가","start":"2026-11-21T20:00:00+09:00","end":"2026-11-21T20:45:00+09:00","active_kcal":"","avg_hr":"","max_hr":""}]}
```

- [ ] `start`/`end`가 `…T…+09:00` 형태다(한글 날짜면 D-3의 `ISO 8601`이 빠짐)
- [ ] `type`에 한글 운동 이름이 들어 있다(두 운동이 서로 달라야 함)
- [ ] 운동 항목 사이에만 쉼표가 있고 맨 끝에는 없다
- [ ] 숫자는 `"142"`처럼 큰따옴표 안에 있다. 심박/칼로리가 `""`이면 그 운동에 워치 샘플이 없다는 뜻이다
- [ ] 평균 < 최대, 둘 다 30~220 사이. 서로 다른 운동에서 값이 달라야 한다(전부 같은 값이면 D-5의 필터 범위가 안 걸린 것)
- [ ] 칼로리가 하루 전체가 아니라 그 운동 구간의 값이다(운동 앱 요약과 비슷)
- [ ] `token`이 내 토큰이고 앞뒤 공백/줄바꿈이 없다

확인 후 임시 `빠른 보기`는 지운다.

### 2-F. 서버로 보내기

14. **URL의 콘텐츠 가져오기**
    - URL: 변수 `URL` · 방법 **POST**
    - 요청 본문: **파일**(File) → 입력으로 변수 `본문`
    - 헤더는 추가하지 않는다(서버는 본문 내용만 읽는다). 본문 형식을 `JSON`으로 고르면 필드 입력 방식이 되어 쓸 수 없으니 반드시 `파일`.
    - → **변수 설정** `응답텍스트`
15. **입력에서 딕셔너리 가져오기**: 입력 `응답텍스트` → **변수 설정** `응답`

### 2-G. 응답 처리와 출력

16. **딕셔너리 값 가져오기**: 입력 `응답`, 키 `ok` → **변수 설정** `성공`
17. **만약** `성공`이 `예`(`true`/`1`)가 **아니면**
    - **딕셔너리 값 가져오기**: 입력 `응답`, 키 `error` → **변수 설정** `오류`
    - **알림 표시**(Show Notification): `운동보드 전송 실패: ⟦오류⟧`
    - **중단 및 출력**: `응답텍스트` (서버가 준 응답 그대로)
18. **그 외(Otherwise)** (같은 `만약` 블록의 두 번째 갈래)
    - **중단 및 출력**: `응답텍스트`
19. **End If**

> 반드시 **"알림 표시"**(Show Notification)를 쓴다. "알림 보기"(Show Alert)는 확인 버튼을 눌러야 해서 자동화를 멈춰 세운다.
>
> 응답을 해석하지 못하면(`ok`가 비어 실패 분기로 감) 서버에는 전송되었을 수도 있다. 시트의 `received_at`이 방금 시각으로 갱신되었는지 확인한다.

`WB 동기화`는 어느 경로에서든 **중단 및 출력**으로 끝나므로 호출한 쪽은 항상 결과 텍스트를 받는다(0건: 정상 모양 텍스트, 성공/실패: 서버 응답). 이 단축어 자체는 성공 시 **조용하다**.

### 첫 실행 점검

`WB 동기화`를 **재생**으로 **수동 실행**한다(입력 없음 → 7일). 자세한 순서는 [5장](#5-첫-실행은-수동으로)을 본다.

## 3. `WB 과거 업로드` 만들기

1. **입력 요청**: 질문 `며칠 전까지 올릴까요?` · 유형 **숫자** · 기본값 `365`
2. **단축어 실행**: `WB 동기화` · 입력 위 결과 → **변수 설정** `결과텍스트`
3. **입력에서 딕셔너리 가져오기**: `결과텍스트` → **변수 설정** `결과`
4. **딕셔너리 값 가져오기**: `ok`
5. **만약** `ok`가 `예`이면
   - 키 `inserted`, `updated`, `rejected`(목록)를 각각 가져오고 `rejected`는 **개수 세기** → `거부수`
   - **알림 표시**: `완료: 추가 ⟦inserted⟧ · 갱신 ⟦updated⟧ · 거부 ⟦거부수⟧`
   - **만약** `거부수`가 `0`보다 크면 **결과 보기**(또는 알림)로 `rejected` 목록(`index`와 `reason`)을 보여 준다
   - **그 외(Otherwise)**
     - **알림 표시**: `실패: ⟦error⟧` (`WB 동기화`가 이미 알림을 띄웠을 수 있다)
   - **End If**

주의:
- 실행 중에는 **화면을 켜고 잠금을 해제한 상태**로 둔다(충전 + 자동 잠금 `안 함` 권장).
- **한 번에 최대 365일**로 쓴다. 한 사람의 1년치는 서버 한도(요청당 1000건)보다 훨씬 적다. 더 오래된 기록이 필요하면 큰 숫자로 한 번 실행해 보고, `too_many`가 나오면 알려 달라.
- 건강 샘플 조회가 운동마다 일어나 1년치는 몇 분 걸릴 수 있다. 앱을 닫지 않는다.

## 4. 자동화 만들기

단축어 앱 → **자동화** → `+` → **개인용 자동화**. 아래 4개를 만든다. 4개 모두 마지막 화면에서 **즉시 실행**을 고르고 **실행 시 알림**(실행 알림)을 **끈다**. 그래야 확인 없이 돈다.

### 자동화 1 — Apple Watch 운동 종료 (실시간)
- 트리거: **Apple Watch 운동** → `종료 시` · `모든 운동`
- 동작: **대기** `60`초 → **숫자** `1` → **단축어 실행** `WB 동기화`(입력: 위 숫자)

### 자동화 2·3·4 — 12:00, 18:00, 22:00 (재동기화)
- 트리거: **하루 중 시간** `12:00`, `18:00`, `22:00` (매일, 각각)
- 동작: **숫자** `7` → **단축어 실행** `WB 동기화`(입력: 위 숫자)

### 잠금 상태에서는?

**아이폰이 잠겨 있으면 건강 데이터를 읽을 수 없다.** 12·18·22시 실행이 모두 잠금 중이면 그 실행들은 실패한다. 다음에 **잠금 해제 상태에서 도는 실행**(다음 운동 종료 자동화, 다음 시간 트리거, 수동 실행)이 같은 7일 창을 다시 보내 빠진 것을 메운다. 7일 넘게 비었다면 `WB 과거 업로드`를 실행한다. 자동화 1은 운동 직후라 폰을 보고 있거나 잠금이 풀려 있을 가능성이 높다.

---

## 5. 첫 실행은 수동으로

1. 아이폰 **잠금 해제 상태**에서 `WB 동기화`를 **재생**한다.
2. **건강 접근 권한** 창이 뜨면 `운동`, `심박수`, `활동 에너지`를 모두 허용한다. **네트워크(웹 요청) 권한** 창이 뜨면 허용한다.
3. 실패 알림이 없으면 성공이다. 대시보드와 시트로 확인한다([7장](#7-대시보드와-시트에서-확인)).
4. 그 다음에 자동화를 만든다. 권한을 한 번도 허용하지 않은 채 자동화가 처음 도는 것은 실패할 수 있다.

## 6. 항상 쓸 수 있는 수동 실행

`WB 동기화`는 언제든 직접 실행해도 된다. 홈 화면에 추가(단축어 상세 → 공유 → `홈 화면에 추가`)하거나 위젯에 올려 두면 한 번 탭으로 최근 7일을 다시 올린다.

## 7. 대시보드와 시트에서 확인

- 대시보드: <https://hyunoh.github.io/wb/> — 새로고침 후 방금 운동이 보이는지
- 시트 `workouts` 탭: 행이 생겼는지, `received_at`(마지막 수신), `first_received_at`(최초 수신), 칼로리/심박이 채워졌는지

**알려진 한계**
- 같은 운동의 식별 키는 `사용자 + 시작 시각(초)`이다. 시작 시각이 다르게 기록되면 **별도 기록**이 된다.
- `duration_min`은 `종료 − 시작`으로 계산되므로 **일시정지 시간이 포함**된다.
- 자정을 넘긴 운동은 대시보드에서 **시작 날짜**의 날로 집계된다.

## 8. 아내에게 공유하기

토큰이 든 단축어를 그대로 공유하면 **내 토큰이 넘어간다.** 아래 순서를 지킨다.

1. `WB 동기화`를 복제해 `WB 동기화 (공유용)`을 만든다. 복사본의 2-A에서 `TOKEN` 텍스트에는 **비밀이 아닌 안내 문구**(예: `여기에 내 토큰`)를 넣고, `USER`는 `wife`로 둔다. 내 토큰이 남아 있으면 안 된다.
2. 복사본에서 **단축어 세부사항**(상단 `i`) → **설정** → **새로운 질문 추가** → `USER`와 `TOKEN` 텍스트 동작을 각각 질문으로 연결한다.
   - 질문 예: `USER` → `wife 라고 입력`, `TOKEN` → `내 쓰기 토큰(WRITE_TOKEN_WIFE)을 붙여넣으세요`
   - **기본 답변은 비워 둔다**(내 값이 기본값으로 남지 않게).
3. **공유 전에** 복사본의 `TOKEN` 텍스트 동작을 열어 내 토큰이 없는지 다시 확인한다.
4. **iCloud 링크**를 만들어 아내에게 보낸다. 링크에는 토큰이 없다. 아내의 `WRITE_TOKEN_WIFE`는 **링크와 따로** 전달한다(URL이나 스크린샷에 넣지 않는다).
5. 아내 폰에서 링크를 열었을 때 **질문 화면이 뜨는지**, `USER`/`TOKEN`을 입력하면 설정되는지, 가져온 뒤 `TOKEN`에 내 토큰이 없는지를 **받는 쪽 입장에서 확인**한다.
6. 자동화는 공유되지 않으므로 아내 폰에서 [4장](#4-자동화-만들기)을 직접 만든다. `WB 과거 업로드`도 필요하면 같은 방식으로 공유한다.

`me` 사용자에 `WRITE_TOKEN_WIFE`를 넣으면 서버가 `unauthorized`로 거부한다.

## 9. 문제 해결

### 요청 단위 오류 (응답이 `{"ok":false,"error":"…"}`)

| `error` | 원인/해결 |
|---|---|
| `unauthorized` | 토큰이 틀렸거나 `USER`와 토큰 주인이 다르다. `USER`는 `me`/`wife`(소문자), 토큰 앞뒤 공백·줄바꿈 제거, 스크립트 속성에서 다시 복사 |
| `bad_request` | 본문 JSON이 깨졌거나 `user`가 틀렸다. "중간 확인"으로 따옴표/쉼표/대괄호 점검. 종류 이름에 특수문자가 있으면 D-4 확인 |
| `too_many` | 한 요청에 1000건 초과. 알려 달라 |
| `busy` | 서버가 다른 요청 처리 중. 잠시 후 다시 실행 |
| `server_error` | 서버 내부 오류. Apps Script 실행 로그 확인 |
| (응답 없음/해석 불가) | 네트워크 권한, URL 오타. 시트의 `received_at`이 갱신됐는지 확인 |

### 행 단위 거부 (`ok:true`인데 `rejected`가 비어 있지 않음)

각 항목은 `{ "index": n, "reason": "…" }`이고 나머지 운동은 정상 저장된다. `index`는 `workouts` 배열의 0부터 시작하는 위치다.

| `reason` | 원인/해결 |
|---|---|
| `invalid_start` / `invalid_end` | 날짜가 ISO 8601이 아님. D-3에서 `ISO 8601` + 시간 포함 확인 |
| `missing_start` | 시작 날짜가 비었다 |
| `missing_type` / `type_too_long` | 종류가 비었거나 60자 초과. D-4의 종류 속성 확인 |
| `end_before_start`, `invalid_duration` | 종료 < 시작, 길이 0 이하 또는 24시간 초과. 단축어의 날짜 변수 확인 |

그 밖의 reason은 `docs/api.md`의 표를 본다.

### 기기에서 흔한 문제

| 증상 | 원인/해결 |
|---|---|
| "건강 데이터에 접근할 수 없음" | 설정 → 건강 → 데이터 접근 및 기기 → 단축어 → `운동`/`심박수`/`활동 에너지` 허용 |
| 자동화가 안 돌거나 값이 비어 들어옴 | **잠금 상태**에서는 건강 데이터를 못 읽는다([4장](#4-자동화-만들기)). 다음 잠금 해제 상태의 실행이 메운다 |
| 심박/칼로리가 빈칸 | 샘플 없음(워치 미착용), `출처` 필터가 워치와 다름, 또는 워치 데이터가 아직 안 옴. 기존 값은 빈 전송으로 지워지지 않고 나중 전송이 채운다 |
| 심박이 운동과 무관하게 큼/작음 | D-5 필터 중 `종료 이전` 또는 `출처`가 빠졌다 |
| 시트에는 있는데 대시보드에 없음 | 새로고침/캐시. 날짜는 서울 시간 기준 **시작 날짜**로 집계 |
| 엉뚱한 날짜/시간 | D-3의 `ISO 8601` + 시간 포함, 아이폰 시간대가 서울인지 확인 |
| 알림이 안 오고 자동화가 멈춤 | "알림 보기"(Show Alert)를 썼다. **"알림 표시"**로 바꾼다 |
| 소수 쉼표 값이 빈칸 | 지역 소수점이 `,`. 지역을 대한민국으로, 그리고 D-6/D-8의 `숫자 반올림` 확인 |

## 10. 기기에서 직접 확인해야 하는 것

- 동작·속성의 한글 이름(`건강 샘플 찾기`, `건강 샘플의 세부사항 가져오기`, `통계 계산`, `날짜 형식 지정`, `텍스트 대치`, `중단 및 출력`, `알림 표시` 등)과 필터 옵션(`같거나 이후`, `출처`)
- 운동 샘플의 **종류 속성**과 값이 한글로 나오는지
- `URL의 콘텐츠 가져오기`에서 본문을 `파일`로 줄 때 텍스트가 그대로 전송되는지
- `입력에서 딕셔너리 가져오기`가 응답을 올바르게 읽는지
- 자동화 4개가 `즉시 실행` + 알림 끄기로 설정되었는지, 잠금 중 실제로 실패하는지(M0 결과와 비교)
- 통계 계산 후 `숫자 반올림`이 빈 입력에서 문제를 일으키지 않는지(D-6, D-8은 개수 > 0일 때만 실행되므로 보통 문제없음)
- 가져오기 질문이 받는 쪽에서 의도대로 동작하는지

## 11. 갱신 지연을 나중에 측정하는 법

시트의 `end`(운동 종료 시각)와 **`first_received_at`**(서버가 이 운동을 처음 받은 시각)의 차이가 전송 지연이다. `received_at`은 재동기화 때마다 바뀌므로 지연 측정에 쓰지 않는다.

1. 빈 열에 아래 수식을 쓴다(2행 기준, 시각이 텍스트로 저장되어 있다는 전제, `E`=end, `K`=first_received_at):
   ```
   =(DATEVALUE(MID(K2,1,10))+TIMEVALUE(MID(K2,12,8)))-(DATEVALUE(MID(E2,1,10))+TIMEVALUE(MID(E2,12,8)))
   ```
   값 × 1440 = 분. `first_received_at`이 비어 있는 행은 열이 추가되기 전 기록이라 측정할 수 없다.
2. 실시간 자동화로 처음 들어온 운동은 지연이 짧고(대기 60초 + 처리), 시간 트리거/수동으로 처음 들어온 운동은 다음 실행 시각까지 길어진다.
3. 지연이 길면 자동화 1의 `대기` 시간을 늘리거나 시간 트리거를 늘린다. 측정값은 PRD의 성공 기준에 반영한다.
