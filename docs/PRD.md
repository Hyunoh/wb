# workoutBoard PRD

> 상태: v0.2 (2026-11-22) · 디자인 확정(A안, 목업 `mockup/`) · M0 측정 결과에 따라 재동기화 주기와 지연 목표 확정 예정

## 1. 개요
- **제품명**: workoutBoard
- **목적**: 애플워치로 기록한 부부 두 사람의 운동을 달력 대시보드로 쉽게 확인한다.
- **사용자**: 나, 아내 (2명, 각자 iPhone과 Apple Watch 사용)
- **주 사용 환경**: iPhone Safari(홈 화면에 추가), 보조로 데스크톱 브라우저
- **필수 지원 기기**: iPhone SE 2세대(375×667, 사용자), iPhone 12 Pro(390×844, 노치, 아내)

## 2. 문제 정의
- 피트니스 앱은 운동을 하나씩 목록으로 보여 줘서, 한 달 동안 언제 얼마나 했는지 한눈에 보기 어렵다.
- 부부가 서로의 운동 현황을 함께 보려면 매번 휴대폰을 건네 봐야 한다.

## 3. 목표 / 비목표
**목표**
- G1. 운동이 끝나면 사람이 손대지 않아도 기록이 자동으로 쌓인다.
- G2. 월 달력에서 날짜마다 두 사람의 운동량(시간)을 한눈에 본다.
- G3. 날짜를 누르면 운동별 상세(종류, 시간, 칼로리, 평균/최고 심박)를 본다.
- G4. 운영 비용 0원, 랩탑 없이 24시간 동작한다.

**비목표 (v1에서 제외)**
- 운동 경로 지도, 심박 그래프 같은 시계열 상세
- 수면, 걸음 수, 활동 링 같은 운동 외 건강 데이터
- 웹에서 기록 직접 입력/수정 (수정이 필요하면 구글 시트에서 직접 고친다)
- 네이티브 iOS 앱

## 4. 시스템 구조
```
[Apple Watch 운동 종료]
      │ (HealthKit 동기화)
      ▼
[iPhone 단축어 자동화] ── POST JSON ──▶ [Google Apps Script 웹앱] ──▶ [Google Sheet]
 (나 / 아내 각자 폰)                         ▲  doPost: 수신·중복제거          (DB 역할)
                                             │  doGet : 조회 API
[GitHub Pages 정적 대시보드] ── GET JSON ────┘
 (달력 UI, 비밀 키로 조회)
```
- 모든 구성 요소가 Google과 GitHub의 무료 인프라에서 돌아가므로 랩탑이 필요 없다.
- 무료 한도(Apps Script 실행 시간, Sheets 1천만 셀)는 하루 몇 건 수준의 사용량에 비해 충분히 넉넉하다.

## 5. 기능 요구사항

### 5.1 데이터 수집 (iOS 단축어)
| ID | 요구사항 |
|---|---|
| C1 | **실시간 전송**: 개인용 자동화 "Apple Watch 운동 → 종료 시"가 방금 끝난 운동을 전송한다. ("묻지 않고 실행"으로 설정) |
| C2 | **일일 재동기화**: 매일 22:00 시간 트리거로 최근 7일 운동을 다시 전송한다. 폰이 잠겨 C1이 실패한 경우를 메운다. |
| C3 | **과거 기록 백필**: 수동 실행 단축어로 지정한 기간(예: 최근 1년)을 한 번에 업로드한다. |
| C4 | 운동마다 보내는 값: 종류, 시작/종료 시각, 시간(분), 활동 칼로리(운동 구간의 Active Energy 합계), 평균/최고 심박(운동 구간의 Heart Rate 샘플 통계) |
| C5 | 단축어 하나를 만든 뒤 iCloud 링크로 아내에게 공유한다. 사용자 이름과 쓰기 토큰만 처음 가져올 때 입력한다. |

### 5.2 백엔드 (Apps Script + Google Sheet)
| ID | 요구사항 |
|---|---|
| B1 | `doPost`: `{token, user, workouts[]}`를 받아 토큰을 검증하고 시트에 **upsert**한다. |
| B2 | 중복 제거 키는 `id = user + "_" + 시작시각(ISO)`이다. 같은 운동을 여러 번 보내도 한 행만 남는다. |
| B3 | `doGet?key=&from=&to=`: 읽기 키를 검증하고 기간 안의 운동을 JSON으로 돌려준다. |
| B4 | 키는 Script Properties에 저장한다(코드에 넣지 않음). 쓰기 토큰은 사용자별로 따로 두고, 읽기 키는 하나를 공유한다. 키를 바꿀 때는 속성 값만 교체한다. |
| B5 | 동시에 들어오는 요청은 `LockService`로 직렬화한다. |

**시트 스키마 (`workouts` 탭)**
| 컬럼 | 예시 | 비고 |
|---|---|---|
| id | `me_2026-11-22T07:10:00+09:00` | PK |
| user | `me` / `wife` | |
| type | `실외 달리기` | 단축어가 준 원문 그대로 저장 |
| start / end | ISO 8601 (+09:00) | |
| duration_min | 32.5 | |
| active_kcal | 310 | 값이 없으면 빈칸 |
| avg_hr / max_hr | 142 / 171 | 값이 없으면 빈칸 |
| received_at | ISO | 마지막 수신 시각 |

### 5.3 대시보드 (GitHub Pages)
| ID | 요구사항 |
|---|---|
| D1 | **월 달력**: 날짜 칸마다 사람별 가로 막대(나=파랑, 아내=주황)와 그날 운동한 분을 표시한다. 막대 길이는 운동 시간에 비례하고, 90분이면 칸을 꽉 채운다. 운동하지 않은 사람은 표시하지 않는다(자리는 비워 둔다). 미래 날짜는 비활성이다. |
| D2 | **보기 필터**: 나 / 아내 / 둘 다 |
| D3 | **날짜 상세**: 날짜를 누르면 바텀시트가 열리고(전날/다음날 이동, 아래로 끌어 닫기), 운동마다 종류 아이콘, 시작 시각, 시간, 활동 칼로리, 평균/최고 심박을 보여 준다. |
| D4 | **월 요약**: 필터 바로 아래, 달력 위에 둔다. 사람별 운동한 날 수, 총 운동 시간(h:mm), 총 칼로리 |
| D5 | 이전 달/다음 달 이동, "오늘"로 돌아가기 |
| D6 | **접근 제어**: 처음 들어오면 읽기 키를 입력받아 `localStorage`에 저장한다. 키가 틀리면 다시 입력받는다. |
| D7 | 모바일 우선 반응형. PWA manifest를 넣어 "홈 화면에 추가"를 지원한다. |
| D8 | 마지막으로 받은 데이터를 `localStorage`에 캐시해 먼저 그리고, 뒤에서 새로 고친다. Apps Script 응답 지연(1~3초)을 가리기 위해서다. |
| D9 | 운동 종류 문자열을 아이콘과 카테고리로 매핑한다. 모르는 종류는 기본 아이콘을 쓴다. |

### 5.4 화면 / 기기 요구사항
| ID | 요구사항 |
|---|---|
| V1 | **iPhone SE 2세대(375×667pt)** 기준: 홈 화면 앱으로 실행하면 헤더, 필터, 달력 6주, 월 요약이 스크롤 없이 한 화면에 들어온다. |

| V4 | 라이트/다크 모드는 시스템 설정을 따른다. |
| V5 | 디자인 기준은 `mockup/`(A안: 사람별 막대 + 분)이다. 실제 구현의 레이아웃, 색, 간격은 목업과 같아야 한다. |

## 6. 비기능 요구사항
- **비용**: 0원 (Google 무료 계정, GitHub 무료 공개 저장소). 저장소에는 키를 넣지 않는다.
- **가용성**: 랩탑과 무관하게 동작한다.
- **개인정보**: 건강 데이터는 비공개 구글 시트에만 둔다. API는 키 없이 호출하면 아무것도 돌려주지 않는다. 대시보드 페이지는 `noindex`로 설정한다.
- **시간대**: 날짜는 Asia/Seoul 기준이고, 시작 시각이 속한 날로 집계한다.
- **기술**: 대시보드는 빌드 도구 없는 vanilla HTML/CSS/JS(ES modules)로 만든다. 백엔드는 Apps Script 파일 하나(`Code.gs`)다.

## 7. 리스크와 대응
| 리스크 | 대응 |
|---|---|
| 아이폰이 잠겨 있으면 HealthKit 읽기가 실패할 수 있다 | C2 일일 재동기화와 upsert로 누락을 자동으로 메운다 |
| 단축어의 운동 샘플에 칼로리와 심박 속성이 직접 없을 수 있다 | 운동 시작~종료 구간의 Active Energy, Heart Rate 샘플을 따로 조회해 합계/평균/최대를 계산한다 (C4) |
| 운동 종류 이름이 언어 설정에 따라 다르다 | 원문을 저장하고 프런트 매핑 테이블로 처리한다 (D9) |
| 읽기 키 유출 | Script Properties에서 키를 바꾸고 대시보드에서 다시 입력한다 |
| Apps Script POST는 302 리다이렉트로 응답한다 | 실행은 리다이렉트 전에 끝나므로 데이터는 저장된다. 단축어에서 응답을 확인하는 단계는 선택 사항으로 둔다 |

## 8. 마일스톤
- **M0 데이터 갱신 검증 (코딩 전)**: 서버 없이 단축어의 "메모에 추가" 동작만으로 측정한다.
  - 테스트 단축어: "Apple Watch 운동 종료 시" 트리거가 실행되면 메모 한 줄을 남긴다. 내용은 `트리거 실행 시각 | 가장 최근 운동의 종료 시각·종류 | 운동 구간의 심박 샘플 수·평균·최대 | 활동 칼로리 합계`
  - 같은 단축어를 10분 뒤, 1시간 뒤에 수동으로 다시 실행해 값이 달라지는지 비교한다. (심박/칼로리가 늦게 동기화되는지 확인)
  - 시나리오 3~5회: 아이폰이 잠금 해제된 상태 / 잠긴 상태 / 아이폰이 멀리 있다가 나중에 연결되는 상태(워치만 들고 운동)
  - 측정 항목: ① 트리거가 실제로 실행되는지와 지연 시간 ② 실행 시점에 운동·심박·칼로리가 이미 들어와 있는지 ③ 잠금 상태에서 읽기에 실패하는지
  - 결과로 정할 것: 실시간 단축어 앞에 대기(예: 1~2분)를 둘지, 일일 재동기화를 하루 1회로 할지 여러 번(예: 12시·18시·22시)으로 할지, 성공 기준(9장)의 지연 목표
- **디자인 확정 (코딩 전)**: 가짜 데이터로 만든 목업을 iPhone 시뮬레이터로 확인하고, 사용자가 승인하면 M1으로 넘어간다.
- **M1 백엔드**: 시트 생성, `Code.gs`(doPost/doGet/upsert), 웹앱 배포, curl로 테스트
- **M2 수집**: 내 폰에 단축어 3종(실시간/일일/백필)을 만들고 백필 실행 → 아내 폰에 공유해 설정
- **M3 대시보드**: 달력, 상세 패널, 필터, 키 입력, GitHub Pages 배포
- **M4 다듬기**: 월 요약, 캐시, PWA, 운동 종류 아이콘

## 9. 성공 기준
- 운동이 끝나고 N분 안에 대시보드 달력에 표시된다. 늦어도 당일 마지막 재동기화 뒤에는 표시된다. (N과 재동기화 주기는 M0 결과로 정한다. 잠정 목표 5분)
- 두 사람의 최근 1년 기록이 빠짐없이 달력에 보인다.
- 아이폰 홈 화면 아이콘으로 열어서 3초 안에 이번 달 달력이 보인다(캐시 기준 즉시).

## 10. 열린 질문 (구현 중 확정)
- 사람별 색상과 이름 표시(현재 "나" / "아내", web/config.js에서 변경)
- 주간 목표(예: 주 150분) 표시는 v2로 미룰지
