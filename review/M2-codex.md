## 발견 사항

1. **major · 운동 종류를 읽는 단계가 확정되지 않았습니다 (C4).** [docs/shortcuts.md:56](docs/shortcuts.md:56), [docs/shortcuts.md:68](docs/shortcuts.md:68), [docs/shortcuts.md:90](docs/shortcuts.md:90)  
   iOS 26.2 액션 자료에는 건강 샘플의 `Type`, `Name`, `Start Date`, `End Date`가 있지만, 한국어 UI에서 `Type` 또는 `Name`이 실제 종목을 반환한다는 근거는 없습니다. `Type`이 `운동`만 반환하면 서버가 그대로 저장하고, 빈 값이면 `missing_type`으로 거부합니다. **수정** — `건강 샘플의 세부사항 가져오기`에 반복 항목을 명시적으로 연결하고, 한국어 iOS 26에서 서로 다른 두 종목의 결과를 비교해 정확한 필드와 표시값을 문서에 고정하세요. 시작·종료는 날짜 변수로 유지하세요. 기본 액션에서 종목을 얻을 수 없다면 운동 종류를 명시적으로 반환하는 HealthKit 연동 액션과 설치·권한 절차가 필요합니다. [iOS 26.2 건강 액션 정의](https://github.com/viticci/shortcuts-playground-plugin/blob/main/codex/skills/shortcuts-playground/HEALTHKIT.md), [Apple HKWorkout](https://developer.apple.com/documentation/healthkit/hkworkout)

2. **major · 건강 샘플 객체를 통계에 바로 넘기고, 빈 목록의 결과를 가정합니다 (C4).** [docs/shortcuts.md:74](docs/shortcuts.md:74)  
   `통계 계산`에는 숫자 목록을 명시적으로 연결해야 단위와 변환 결과를 확인할 수 있습니다. 문서의 암묵 변환이 실패하거나, 샘플 없는 운동에서 평균·최대 계산이 중단되면 해당 운동 뒤의 기록까지 전송되지 않을 수 있습니다. **수정** — 심박과 활동 칼로리 각각에서 샘플의 `값(Value)`과 `단위(Unit)`를 확인하고 bpm·kcal 숫자 목록으로 만든 뒤 평균·최대·합계를 계산하세요. 목록이 비면 통계 동작을 건너뛰고 해당 필드를 빈 값으로 지정하세요. 운동마다 값을 초기화하고, 샘플 0개·1개인 운동을 확인하세요. 샘플 1개면 평균과 최대는 같습니다. [iOS 26.2 건강 액션 정의](https://github.com/viticci/shortcuts-playground-plugin/blob/main/codex/skills/shortcuts-playground/HEALTHKIT.md)

3. **major · 시간 필터 두 방식이 서로 다른 샘플을 집계하고, 출처가 섞입니다 (C4).** [docs/shortcuts.md:74](docs/shortcuts.md:74), [docs/shortcuts.md:83](docs/shortcuts.md:83)  
   `시작 이후 AND 종료 이전`은 경계에 걸친 샘플을 제외할 수 있고, `시작 날짜가 사이`는 운동 종료를 넘어가는 에너지 샘플까지 포함할 수 있습니다. 시간만으로 조회하면 같은 구간의 iPhone·Watch·다른 앱 샘플이 합산돼 칼로리가 부풀거나 심박 평균이 달라질 수 있습니다. **수정** — 운동에 연결된 샘플을 조회할 수 있으면 우선 사용하세요. 기본 단축어의 시간 조회를 쓴다면 `모든 건강 샘플`에서 조회하고, 운동별 출처 우선순위와 경계 포함 규칙을 고정하세요. 날짜 비교에는 운동의 원본 시작·종료 변수를 사용하세요. 필터에 필요한 날짜 속성이 없으면 넓게 조회한 뒤 반복문에서 샘플 시작·종료를 비교하고, 자정을 넘는 운동과 출처가 겹치는 운동을 피트니스 기록과 대조하세요. [Apple HKWorkout](https://developer.apple.com/documentation/healthkit/hkworkout), [Apple 건강 데이터 출처 관리](https://support.apple.com/en-gb/108779)

4. **major · 직접 조립한 JSON은 깨질 수 있고, 지역화 숫자는 조용히 오저장됩니다.** [docs/shortcuts.md:85](docs/shortcuts.md:85), [docs/shortcuts.md:97](docs/shortcuts.md:97), [docs/api.md:172](docs/api.md:172), [backend/Code.gs:105](backend/Code.gs:105)  
   값에 큰따옴표·역슬래시·실제 줄바꿈이 들어가면 JSON이 깨지거나 값이 바뀝니다. 쉼표로 소수를 표시한 문자열은 JSON으로 유효하지만, 백엔드에서 `"310,4"`는 `3104`, `"1.204,5"`는 반올림 후 `1`로 저장되는 것을 재현했습니다. `"1,204"`는 현재 파서에서 `1204`이므로 쉼표를 일괄 치환해도 해결되지 않습니다. **수정** — 항목을 딕셔너리로, `workouts`를 딕셔너리 배열로 유지하고 JSON 직렬화에 이스케이프를 맡기세요. 측정치는 JSON 숫자로 보내고 누락 시 키를 생략하거나 `null`을 쓰세요. 0건이면 전송을 생략하고 0건 결과를 반환하세요. 전송하는 경로를 택한다면 `workouts: []`가 계약상 유효합니다. [Apple 단축어 딕셔너리 안내](https://support.apple.com/en-ie/guide/shortcuts/apd43b69f337/ios)

5. **major · C1·C2의 트리거는 지원되지만 잠금 상태에서의 복구가 보장되지 않습니다.** [docs/shortcuts.md:162](docs/shortcuts.md:162), [docs/shortcuts.md:173](docs/shortcuts.md:173), [docs/shortcuts.md:182](docs/shortcuts.md:182)  
   Apple은 `Apple Watch 운동` 종료와 `특정 시간` 자동 실행을 지원합니다. 즉시 실행은 트리거의 확인을 생략하는 설정이며, 잠금 중 HealthKit 조회는 실패할 수 있습니다. 60초 대기 도중 잠기거나 12·18·22시 모두 잠겨 있으면 다음 예약 실행도 같은 이유로 실패합니다. 7일 창을 넘기면 일반 재동기화에서도 빠집니다. **수정** — 자동화 편집기에서 즉시 실행을 설정하고 `실행 시 알림`이 표시되면 끄도록 안내하세요. §0의 `개인용 자동화 허용` 전역 설정은 선행 조건에서 빼세요. 핵심 단축어를 잠금 해제 상태에서 먼저 실행해 건강 및 네트워크 권한을 처리하고, 잠금 상태에서 C1의 60초 대기와 C2의 실제 저장 결과를 확인하세요. 누락이 지속되면 잠금 해제 후 수동 동기화, 7일이 지났으면 백필을 안내하세요. [Apple 자동화 트리거](https://support.apple.com/en-il/guide/shortcuts/apd932ff833f/ios), [Apple 자동 실행 설정](https://support.apple.com/ko-kr/guide/shortcuts/apd602971e63/9.0/ios/26), [HealthKit 잠금 오류](https://developer.apple.com/documentation/healthkit/hkerror/code/errordatabaseinaccessible)

6. **major · 수동 백필이 결과를 안정적으로 받지 못하고, 제시한 분할은 요청 크기를 줄이지 않습니다 (C3).** [docs/shortcuts.md:137](docs/shortcuts.md:137), [docs/shortcuts.md:188](docs/shortcuts.md:188)  
   §3은 `WB 동기화`가 응답을 반환한다고 가정하지만 §1의 반환은 선택 사항이고, 운동 0건이나 서버 오류에서는 출력 없이 중단합니다. 또 `180 → 365`를 실행하면 두 번째 호출이 여전히 전체 365일을 읽으므로 1,000건을 넘으면 `too_many`가 반복됩니다. **수정** — `단축어 실행`의 `입력`에 `숫자` 또는 `입력 요청`의 매직 변수를 명시하고, 내부 단축어가 성공·0건·서버 오류에서 일관된 딕셔너리를 `중단 및 출력`으로 반환하게 하세요. 백필은 시작·끝을 받는 서로 겹치지 않는 구간이나 요청당 최대 1,000건 배치로 나누고, 부분 실패 시 실패한 구간부터 다시 실행할 수 있게 하세요. [Apple의 단축어 실행 동작 안내](https://support.apple.com/ko-kr/guide/shortcuts/apdc11deb2c1/9.0/ios/26), [Apple의 중단 및 출력 안내](https://support.apple.com/ko-kr/guide/shortcuts-mac/apd455c82f02/mac)

7. **major · POST 응답을 읽지 못하는 경우와 행 거부를 성공으로 오인할 수 있습니다.** [docs/shortcuts.md:127](docs/shortcuts.md:127), [docs/shortcuts.md:137](docs/shortcuts.md:137), [docs/shortcuts.md:154](docs/shortcuts.md:154)  
   `URL의 콘텐츠 가져오기`의 POST·파일 본문 옵션은 존재합니다. 텍스트 변수가 그대로 전송되는지와 Apps Script의 302 뒤 최종 JSON을 읽는지는 현재 테스트 범위 밖입니다. 저장 후 응답을 놓칠 수 있고, `ok: true`여도 모든 행이 `rejected`일 수 있습니다. **수정** — 직렬화된 UTF-8 JSON을 파일 본문에 연결하고 실기기에서 `/exec` 전송과 최종 응답을 함께 확인하세요. 필요하면 `입력에서 딕셔너리 가져오기`로 변환한 뒤 같은 딕셔너리에서 `ok`를 불리언으로 읽고, `inserted`, `updated`, `rejected`를 확인하세요. 수동 실행에서는 거부 이유를 표시하고, 자동화의 오류 안내에는 확인 버튼을 기다리는 `알림 보기` 대신 시스템 알림을 쓰세요. 응답을 못 읽었으면 시트에서 저장 여부를 확인할 수 있게 안내하세요. [Apple의 URL 요청 옵션](https://support.apple.com/en-lk/guide/shortcuts/apd58d46713f/ios), [Google의 Apps Script 리다이렉트](https://developers.google.com/apps-script/guides/content), [Apple의 시스템 알림 동작](https://support.apple.com/ko-kr/guide/shortcuts-mac/apd2175adcab/mac)

8. **major · 재전송은 같은 키에서만 멱등이며, 늦게 도착한 빈 값이 기존 측정치를 지웁니다.** [docs/shortcuts.md:16](docs/shortcuts.md:16), [backend/Code.gs:211](backend/Code.gs:211), [backend/Code.gs:300](backend/Code.gs:300)  
   같은 사용자의 시작 초가 같으면 서로 다른 운동도 마지막 행으로 덮입니다. 같은 운동을 iPhone과 Watch 또는 외부 앱이 1초 차이로 저장하면 두 행이 남습니다. 정상 칼로리 뒤에 빈 값이 오면 `null`로 덮이는 것도 재현했습니다. 잠금과 서버 락은 이 문제를 해결하지 못합니다. **수정** — 현재 키의 한계를 명시하고, Watch 교체 이력을 포함해 사용자별로 신뢰하는 출처를 정하고 겹치는 기록의 선택 우선순위를 적용하세요. 잠정 수집에서는 서버가 기존의 유효한 측정치를 보존하도록 병합 정책을 정하세요. 자동으로 병합할 근거가 부족한 서로 다른 시작 시각의 기록은 별개로 남을 수 있음을 설명하세요.

9. **minor · 조회 창, 시간대, 운동 시간의 의미가 불분명합니다.** [docs/shortcuts.md:47](docs/shortcuts.md:47), [docs/shortcuts.md:71](docs/shortcuts.md:71), [docs/shortcuts.md:244](docs/shortcuts.md:244), [docs/api.md:174](docs/api.md:174)  
   빈 값·문자 입력이 `숫자` 변환에서 항상 0이 된다는 근거가 없습니다. 시작일 하한만 쓰면 미래 기록도 포함되고, 하한 직전에 시작해 창 안에서 끝난 운동은 빠집니다. `ISO 8601`에 시간 포함은 지원되며 `Z`와 다른 유효 오프셋도 서버가 받습니다. 자정을 넘기는 운동의 경과 시간은 계산되지만 대시보드는 서울 기준 시작일에 귀속합니다. 일시정지한 운동에서는 `end - start`가 피트니스의 실제 운동 시간보다 길 수 있습니다. **수정** — 기본값 7을 먼저 설정하고 유효한 양의 정수 입력만 적용하세요. 시작 기준으로 조회할지 종료 기준으로 조회할지 정하고, 상한은 실행 시각으로 고정하세요. 최근 1일·7일이 현지 달력일 차감인지 24·168시간인지도 명시하세요. 오프셋을 유지하고 서울 시간대로 기기를 바꾸는 안내는 제거하세요. C4의 시간이 실제 활동 시간이면 건강 샘플의 `Duration`을 분으로 변환해 `duration_min`으로 보내세요. [Apple의 ISO 8601 포맷](https://support.apple.com/en-euro/guide/shortcuts/apdfd459e13d/ios), [Apple의 운동 일시정지와 활동 시간](https://developer.apple.com/documentation/healthkit/hkworkout/workoutevents)

10. **minor · 가져오기 질문 경로와 토큰 확인 절차가 불완전합니다 (C5).** [docs/shortcuts.md:107](docs/shortcuts.md:107), [docs/shortcuts.md:208](docs/shortcuts.md:208)

[Apple 가져오기 질문](https://support.apple.com/ko-kr/guide/shortcuts/apdf330fd3a0/9.0/ios/26), [Apple iCloud 링크 공유](https://support.apple.com/en-gb/guide/shortcuts/apdf01f8c054/9.0/ios/26)

11. **minor · 잘못된 장 번호와 오류 안내가 조립 및 문제 해결을 방해합니다.** [docs/shortcuts.md:43](docs/shortcuts.md:43), [docs/shortcuts.md:145](docs/shortcuts.md:145), [docs/shortcuts.md:156](docs/shortcuts.md:156), [docs/shortcuts.md:231](docs/shortcuts.md:231)
