# 백엔드 배포 가이드 (Google Apps Script + Google Sheet)

코딩 경험이 없어도 따라 할 수 있도록 순서대로 적었다. 소요 시간은 약 10분이다.
API 사양은 [`../docs/api.md`](../docs/api.md)를 본다.

## 1. 구글 시트 만들기
1. <https://sheets.google.com> 에서 **빈 스프레드시트**를 새로 만든다.
2. 이름을 `workoutBoard` 등으로 바꾼다. (탭은 setup이 자동으로 만든다.)
3. **비공개로 둔다.** 공유하지 않는다. 건강 데이터가 들어간다.

## 2. Apps Script 열고 코드 붙여넣기
1. 시트 메뉴에서 **확장 프로그램 > Apps Script** 를 연다. (이 시트에 묶인 스크립트가 만들어진다.)
2. 왼쪽 파일 목록의 `Code.gs` 내용을 모두 지우고 이 저장소의 `backend/Code.gs` 내용을 붙여넣는다.
3. 왼쪽 톱니바퀴 **프로젝트 설정**에서 **"'appsscript.json' 매니페스트 파일을 편집기에 표시"** 를 체크한다.
4. 왼쪽 파일 목록에 나타난 `appsscript.json`을 열어 `backend/appsscript.json` 내용으로 통째로 바꾼다.
   (시간대 Asia/Seoul, V8, 웹앱 실행 권한 설정이 들어 있다.)
5. 상단 디스크 아이콘(또는 Cmd/Ctrl+S)으로 저장한다.

## 3. setup() 한 번 실행
1. 편집기 상단 함수 선택 드롭다운에서 **`setup`** 을 고르고 **실행**을 누른다.
2. 처음에는 권한 승인 창이 뜬다. **권한 검토 > 계정 선택 > 고급 > (프로젝트 이름)(안전하지 않음)으로 이동 > 허용**.
   (내가 만든 스크립트라서 나오는 경고다.)
3. 실행 로그에는 키 값이 출력되지 않고 생성/유지 여부만 나온다. **프로젝트 설정(톱니) > 스크립트 속성**에서 값을 확인한다.
   - `SPREADSHEET_ID`: 시트 ID (자동 저장, 건드리지 않는다)
   - `WRITE_TOKEN_ME`: 내 쓰기 토큰 (내 단축어에 입력)
   - `WRITE_TOKEN_WIFE`: 아내 쓰기 토큰 (아내 단축어에 입력)
   - `READ_KEY`: 대시보드 읽기 키
4. **`setup`은 반드시 배포(4단계) 전에 실행한다.** 웹앱은 `SPREADSHEET_ID`로 시트를 열기 때문이다.
5. 시트로 돌아가면 `workouts` 탭과 헤더 행이 생겨 있다. `setup`은 여러 번 실행해도 안전하며 기존 키를 바꾸지 않는다.

> 키는 비밀번호처럼 다룬다. 저장소(GitHub)에 올리지 않는다.

## 4. 웹 앱으로 배포
1. 오른쪽 위 **배포 > 새 배포**.
2. 톱니(유형 선택) > **웹 앱**.
3. 설명: 아무거나(예: v1). **다음 사용자 인증 정보로 실행: 나**, **액세스 권한이 있는 사용자: 모든 사용자**.
   (키 검증으로 보호되므로 익명 접근이어야 아이폰/브라우저에서 호출할 수 있다.)
4. **배포**를 누르고 나오는 **웹 앱 URL**(`https://script.google.com/macros/s/.../exec`)을 복사한다.
   이 URL이 단축어와 대시보드에 들어갈 주소다.

## 5. 동작 확인 (스모크 테스트)
```bash
URL='https://script.google.com/macros/s/XXXX/exec' \
WRITE_TOKEN='내 쓰기 토큰' READ_KEY='읽기 키' \
./scripts/smoke.sh
```
`스모크 테스트 통과`가 나오면 성공이다. 테스트 행(`me_2000-01-01T00:00:00+09:00`, 2000-01-01)은
실제 달력에 나타나지 않으며, 원하면 시트에서 그 행을 직접 지운다.

직접 호출해 보기:
```bash
URL='https://script.google.com/macros/s/XXXX/exec'
READ_KEY='읽기 키'
curl -sL -G --data-urlencode "key=$READ_KEY" \
  --data-urlencode "from=2026-11-01" --data-urlencode "to=2026-11-30" "$URL"
```
주의: POST 확인은 `curl -sL --data ...` 로 하고 `-X POST`를 붙이지 않는다(302 리다이렉트를 GET으로 따라가야 함).

### 배포 후 확인 체크리스트
- [ ] 스모크 테스트 통과
- [ ] (CORS 확인) 대시보드가 올라갈 주소(나중에 GitHub Pages)를 Safari **비공개 브라우징 창**(구글 로그인 안 된 상태)에서 열고, 개발자 도구/콘솔 또는 대시보드에서
      `fetch()` GET이 올바른 키면 JSON, 틀린 키면 `unauthorized`를 돌려주는지 확인한다.
      이 항목은 M3에서 실제 대시보드로 확인한다.

## 6. 코드를 고친 뒤 다시 배포 (URL 유지)
새 배포를 만들면 URL이 바뀌므로, 기존 배포를 수정한다.
1. **배포 > 배포 관리** > 기존 배포의 연필(수정) 아이콘.
2. **버전: 새 버전** 선택 > **배포**.
3. URL은 그대로다. (`setup`이 새로 필요하면 다시 실행해도 기존 키는 유지된다.)

## 7. 키 교체
1. **프로젝트 설정 > 스크립트 속성**에서 해당 속성(`READ_KEY`, `WRITE_TOKEN_ME`, `WRITE_TOKEN_WIFE`)의 값을 새 값으로 편집한다
   (24자 이상 임의 문자열). 또는 속성을 삭제하고 `setup`을 실행하면 새 키가 생성된다.
2. 재배포는 필요 없다. 바로 적용된다.
3. 읽기 키: 대시보드에서 새 키를 다시 입력한다. 쓰기 토큰: 해당 사람의 단축어 토큰을 바꾼다.

## 8. 로컬 테스트
Node.js(22 이상)만 있으면 된다. 외부 패키지는 없다.
```bash
node --test backend/test/
```

## 문제 해결
- 응답이 `unauthorized`: 키/토큰 오타, 또는 `user`와 토큰 불일치.
- 응답이 `busy`: 동시에 여러 요청이 몰린 것. 잠시 후 재시도.
- 응답이 `server_error`: Apps Script **실행** 메뉴(로그)에서 상세 오류를 확인한다.
- 배포 후 코드 변경이 반영 안 됨: 6번처럼 **새 버전**으로 재배포했는지 확인한다.

## 변경 이력

### 코드 업데이트 후 재배포 (2026-11, 단축어 수집 대응)

Apps Script는 코드를 저장만 해서는 기존 웹앱 URL에 반영되지 않는다. 이번 변경(갱신 시 측정값 보존, `first_received_at` 열 추가, 쉼표 숫자 규칙)을 적용하려면:

1. `backend/Code.gs` 내용을 편집기 `Code.gs`에 다시 붙여넣고 저장한다.
2. **배포 > 배포 관리 > 연필(수정) > 버전: 새 버전 > 배포**. URL은 바뀌지 않는다. ("새 배포"를 누르면 URL이 바뀌니 주의)
3. `setup()`을 다시 실행할 필요는 없다. 10열이던 시트는 **다음 쓰기 때** `first_received_at` 헤더(11열)가 자동으로 추가된다. 기존 행의 이 열은 비어 있다(알 수 없음).
4. 재배포 후 `./scripts/smoke.sh`를 실행해 통과하는지 확인한다.
